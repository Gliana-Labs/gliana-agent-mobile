## IF PORTING AN EXISTING APPLICATION OVER TO MOBILE, WHAT MAJOR FEATURES OR NEW SIGNIFICANT MOBILE DEVELOPMENT HAVE YOU DONE?

```
Gliana Agent began as a web app (agent.glianalabs.com). The Android app is a
native rebuild in Expo/React Native, not a webview, and most of the work only
exists on mobile:

• Mobile Wallet Adapter end to end. Payments are signed in the user's own
  wallet — Seed Vault on the Seeker — and settle straight from it; we never
  hold a balance or custody funds. Getting this working on-device took one
  non-obvious fix: wallets re-serialise a transaction before signing, so the
  signed wire bytes must be submitted verbatim rather than re-encoded from our
  own object, or the signature verifies against the wrong message.

• The SKR Arena — a daily on-chain contest with its own Anchor program, live on
  mainnet. This is new, mobile-only, and is described in the SKR answer below.

• A game map as the home screen, instead of a chat box. The overworld art was
  generated by Gliana Agent itself through the same paid API the app sells, and
  the buildings are the navigation. Panning runs on the UI thread through
  Reanimated shared values, and travel is a tap gesture racing the pan, because
  a Pressable nested in a panning transform loses every touch that drifts.

• A pixel-art interface built for a phone: Press Start 2P for chrome only, hard
  offset shadows instead of blurs, 2px borders, and haptics on every committing
  action. Five synthesised arcade blips (no sampled audio, no licence question),
  mixed so they never interrupt the user's music and stay silent on a silenced
  phone.

• Mobile-native plumbing: camera and gallery attachments feeding image-to-image
  and multi-reference models, generated media saved to the device gallery,
  conversations and the wallet session persisted through AsyncStorage so a cold
  start does not re-open the wallet sheet, and an adaptive launcher icon.

• Published on the Solana dApp Store (com.glianalabs.agent).
```

## DOES YOUR APPLICATION HAVE AN SKR INTEGRATION? IF SO, HOW?

```
Yes. SKR is the currency of the Arena, a daily contest that runs inside the
app on its own Anchor program, live on mainnet:

  program  2CdzdzR1hj6w1ZjXLgvk3o2Saq5sXd1ufQ3Toww4PPHQ
  token    SKRbvo6Gf7GondiT3BbTfuRDPqLWei4j2Qy2NPGZhW3 (real SKR, 6 dp)

The loop: every UTC day has a theme. You generate an image for it with any of
the 116 models the app sells (paid in USDC, unchanged), then pay a 5 SKR entry
fee to put that result in the arena. Voting is free and one per wallet. When
the day ends, the pot pays out 60% to the winner, 25% split across places 2-5,
and 15% to everyone who voted for the winner.

Four things make it a real integration rather than a token sticker:

• The pot is held by the program. The vault is a token account owned by the
  round's PDA, so only program instructions can move it — we cannot.

• Payouts are permissionless. `claim_place` can be called by anyone once the
  round has ended, so pots still pay out if we disappear. Places claim
  individually rather than one settle transaction, because paying everyone at
  once caps a round at whatever fits in 1232 bytes.

• Holding SKR is enforced on-chain, not in the UI. The program reads the
  entrant's own token account and charges 100+ SKR holders 20% less. A client
  that lies about its balance gets its transaction rejected.

• The entry fee is charged AFTER a successful generation, never before. A model
  that fails must not cost anyone SKR.

Self-votes are refused (the voter share would otherwise pay you for backing
yourself), and one vote per wallet is enforced by the existence of a Vote PDA
rather than by anything we track.

A round is a UTC day and its id IS the day number, so every client derives
today's round and its theme with no server involved. The first player of the
day creates the round account; the app derives the theme it expects from the
same fixed list, so the opener cannot write a theme nobody is playing for.

Honest scope note: generations are still paid in USDC, because verifying a
payment before running a model happens in our gateway, and this hackathon's
scope is the mobile app. SKR-for-inference is roughly a day of work on top and
is the direction we want.
```
